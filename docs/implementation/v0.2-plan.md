## 進め方

単位は 3 つの系統に分かれ、系統の間はほぼ独立している。

| 系統 | 単位 | 先頭 |
|---|---|---|
| A. ゲーム API | M2-01〜03, M2-05, M2-15〜25 | M2-01 |
| B. ネットワーク | M2-04, M2-06〜10 | M2-06 |
| C. テキスト | M2-11〜14 | M2-11 |

**M2-01 を最初にやる**（並べる基準 2）。ハンドラの文脈とプレイヤーのハンドルは、A の全単位と M2-14（Audience）の形を決める。
誤りが後になるほど直せないので、B・C より先に計画書を書いて確定させる。B と C は M2-01 と並行してよい。

各単位は 1 PR 相当。着手するときに単位ごとの計画書（`*-plan.md`）を書き、完了したら [backlog.md](backlog.md) を ✅ にする。
v0.1 と同じく、新しいパケットの形式は server.jar の実 codec で確かめ、テストはハーネス（`test-util`）とボットで書く。
ボットに足す操作（plugin message・コマンド・インベントリのクリック等）は、それを使う単位で足す。

## 先に決めること（M2-01 で決めた。[handler-context-plan.md](handler-context-plan.md)、D31）

- **ハンドラの文脈の型**（D29 の (1)）: `Ctx`（状態）を受ける。`World` は `Ctx` と `EventNode<Ctx>` を並べて持ち、ローダーの型引数は消えた。
  `ctx.spawn`・スケジューラ・コマンド・Audience が同じ型を受ける。
- **プレイヤーのハンドル**（D29 の (5)）: `PlayerId { uuid, serial }`。入室のたびに `serial` が増え、退出した人のハンドルは何も指さない。
  エンティティの ID は M2-17 で決める（プレイヤーを同じ表に載せるなら `From<PlayerId>` で足せる形にしてある）。
- **利用者データの置き場**（REQ-API-007）: プレイヤーの記録に型付きの key で引く表を持ち、`PlayerId` から引く。実装と key の形は M2-19 の計画書で決める。

決めたことは D31 に残し、architecture.md の「イベント」を直した。
