# チャンク送信の分割とキャッシュ 実装計画（M1-21）

> **Status**: 計画 — 2026-10-01

要件: REQ-WORLD-002（view distance に応じたチャンクの送信）と、M1-18 の計測の前提。
入室のたびに全チャンクをその場でエンコードして instance のスレッドを塞ぐ問題（M1-13・M1-16 で観測）を直す。`World` の送信の仕組みを変えるので、ここに設計を置く。

## 測ったこと

- `view_distance = 8`（289 チャンク）の入室 1 回が、release で約 0.5 秒、debug で約 12.7 秒。時間はほとんどエンコード（`to_packet`）で、`FlatGenerator` の生成は軽い
- release の lobby にボット 10 体を入れると `can't keep up, skipping ticks behind_ms=6310`、5 体で 2836
- 全員が**同じチャンク**を同じ形でエンコードしている。同じスポーンに入る N 人は N 回エンコードする

## 設計

二つを組み合わせる。A は 1 tick のコストの上限を保証し、B は 2 人目以降の入室コストをほぼ 0 にする。

### A: tick ごとの予算

- `World::chunks_per_tick`（公開、既定 8）: 1 人が 1 tick に受け取るチャンクの数の上限
- プレイヤーごとに未送信のキュー（近い順）を持つ。`ChunkTracker::update` が返す `send` を積む
- 入室とチャンクの境界またぎでは、**最初の 1 バッチをその場で送る**。近い順なので、立っているチャンクが最初に届く。残りは `tick()` が `chunks_per_tick` ずつ、バッチ（`ChunkBatchStart` … `ChunkBatchFinished`）にして送る
- チャンクの境界をまたいだとき、もう要らない未送信のチャンクはキューから外す（`unload` に入ったもの）。キューは新しい中心からの距離で並べ直す
- 送信に失敗したプレイヤーは今までどおり `leave`

### B: エンコード済みパケットのキャッシュ

- `World` が `ChunkPos` ごとにエンコード済みの本体（パケット id を含む）を持つ。同じチャンクを送るときはそれを複製して使う
- `set_block` が、書き換えたチャンクのキャッシュを捨てる（次に送るときにエンコードし直す）。チャンクを書き換える経路は `set_block` だけ（M1-15）
- キャッシュはチャンクと同じ寿命。チャンクは今も破棄しない（M1-15 の ponytail）ので、メモリはロードしたチャンクの数に比例する

### 動作の変わるところ

入室したプレイヤーは、最初のバッチ（`chunks_per_tick` 個）だけをその場で受け、残りは次の tick から届く。`chunks_per_tick` を大きくすれば従来の「全部その場で」に戻る。

## v0.1 でやらなかったこと（後で対応する）

| 項目 | 今の動き | なぜ外したか | 受け皿 |
|---|---|---|---|
| クライアントの `ChunkBatchReceived`（受け取れる速さの申告） | 読み捨て。予算は固定 | 速さの制御は、遅い回線の計測（M1-18 の次）で必要になってからでよい | v0.2 以降 |
| 全プレイヤー合計の 1 tick の上限 | プレイヤーごとの予算だけ。N 人が同時に入ると N × 予算 | 2 人目以降はキャッシュで安い。本当に問題になるかは M1-18 の計測で見る | M1-18 の結果次第 |
| キャッシュとチャンクの破棄 | 破棄しない（メモリはロード済みの数に比例） | M1-15 の ponytail と同じ。破棄は永続化（REQ-WORLD-003）と一緒に決める | REQ-WORLD-003 |
| 送信用チャンネルの本体が `Vec<u8>`（宛先ごとに複製） | 複製する | 共有（`Arc`）にするには `Sessions` と接続側の型を変える。コストはキャッシュの複製（メモリコピー）だけ | M1-18 の計測で見て必要なら |

## テスト

- 予算: `chunks_per_tick` が 4 のとき、入室した直後は 1 バッチ（4 個、最初が立っているチャンク）で、tick ごとに 4 個ずつ、25 個になるまで届く。`ChunkBatchFinished` の count が各バッチの個数に合う
- 近い順: 最初のチャンクは本人のいるチャンク
- 境界またぎ: 予算より多いチャンクが新たに要るとき、最初のバッチはその場で、残りは tick ごと。外れた未送信のチャンクは送られず、`ForgetLevelChunk` の対象になる
- 途中で退出しても残りのキューで何も起きない（エラーにならない）
- キャッシュ: 2 人目の入室は同じバイト列を受け取る。`set_block` のあとに入室した人は、書き換えたあとのチャンクを受け取る
- 既存のテストは、`chunks_per_tick` を大きくして（従来どおり全部その場で）そのまま通す

## 動作確認

- `mise run check`
- release の lobby にボット 10 体（`cargo xtask bot --count 10 --seconds 5`）を入れ、`can't keep up` が出ないこと（修正前は `behind_ms=6310`）
